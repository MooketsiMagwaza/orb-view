# Content

The network is data. Nothing about concepts, links, or paths lives in code, so it can be read, edited, diffed, and generated by any tool that speaks JSON.

```text
content/
├── concepts/        one file per cluster of ideas: cosmos.json, security.json, music.json, …
├── links/           themed lists of extra cross-links: tech.json, science.json, …
├── categories/      one file per learning path: me-entropy-taoism.json, tech-networking.json, …
├── depth/           the four layers (picture, mechanism, detail, principles) for concepts written in full
├── library/         the faculties and departments at the top of the library
└── *.schema.json    editor schemas for each of the above
```

Add `"$schema": "../concept.schema.json"` (already present) and most editors will validate and autocomplete as you type.

## Concept files

Each file in `concepts/` is a cluster:

```json
{
  "$schema": "../concept.schema.json",
  "cluster": "networking",
  "description": "What this file is about.",
  "concepts": [
    { "id": "dns", "title": "DNS", "voice": "precise", "orb": "solving", "parents": ["networks"], "wiki": "Domain Name System", "summary": "…" }
  ],
  "links": [ ["dns", "trust"], ["dns", "cache"] ]
}
```

One concept per line keeps diffs readable. A concept has:

| Field | Meaning |
| --- | --- |
| `id` | Unique, kebab-case, stable. Everything else refers to it. |
| `title` | The label under the orb. 24 characters at most. |
| `summary` | The short explanation shown on hold, 15–65 words, in the branch's voice. |
| `voice` | `restless`, `precise`, `layered`, `human`, `quiet`, `mechanical`, `vast`, or `lucid`. Sets the blue, the speed, and the pitch. |
| `orb` | One of the nine `thinking-orbs` forms. See [ORBS.md](../ORBS.md). |
| `parents` | Where this idea comes from. The first parent decides where it sits; extra parents add connections. |
| `wiki` | The exact English Wikipedia article title, used by the info sheet. |
| `nasa`, `met` | Optional search phrases for the NASA image library and The Met's public-domain collection. |
| `sensitive` | `true` for subjects that need care (religion, weapons, conflict, identity, death). |
| `layer` | `2` for ideas that only appear when their parent is tapped a second time. Needs exactly one parent. |

Rules the validator enforces: no more than ten children in one ring (nine around the root), siblings avoid sharing an orb form, every concept is reachable from `entropy`, and there are no cycles.

## Links

`links` pairs connect ideas across branches. A pair is symmetric, so list it once. Parent/child pairs belong in `parents`, not here. Put a link in the cluster file that owns one of its ends, or, for themes that cross many clusters, in `links/`. Aim for real relationships: a link should be something a curious person would want to follow.

## Categories (paths)

A category is a way in: an entry concept and a short ordered trail of ideas to learn one at a time.

```json
{
  "id": "tech-networking",
  "group": "Tech",
  "order": 2,
  "title": "Networking",
  "blurb": "How machines talk: packets, addresses, protocols, names, and routes.",
  "orb": "connecting",
  "entry": "networks",
  "path": ["networks", "packets", "osi-model", "ip", "tcp", "dns"]
}
```

`group` is one of `Me`, `Tech`, `People`, `Science`, `Culture`, `Abstract` (a new group name simply appears after them). The path must start at `entry` and only list real concept ids.

## Depth files

Each file in `depth/` holds the full explanation of some concepts, in four layers, with what each one is built on:

```json
{ "id": "tls", "picture": "…", "mechanism": "…", "detail": "…\n\nA second paragraph.", "principles": "…",
  "example": { "label": "Watch a handshake", "code": "openssl s_client -connect example.com:443 -brief" },
  "requires": ["tcp", "public-key", "key-exchange", "certificates"] }
```

The validator checks lengths (picture 4–70 words, mechanism 20–120, detail 30–240, principles 20–130), that every `requires` is a real concept, and that prerequisites do not loop. It warns when something is built on a concept that has no depth yet, which is the list of what to write next. See [LIBRARY.md](../LIBRARY.md).

### Writing depth without escaping code

Code inside JSON needs every quote and newline escaped. Write the layers as a module with backtick strings and let `tools/build-depth.mjs` produce the JSON:

```js
// my-depth.mjs
export default {
  description: "What this file covers.",
  depth: [{
    id: "hash-tables",
    picture: `A cabinet of numbered drawers.`,
    mechanism: `…`,
    detail: `First paragraph.

Second paragraph.`,
    example: { label: "A tiny table", code: `
table = {}
table["apple"] = 3
print(table)
` },
    principles: `…`,
    requires: ["arrays"],
  }],
};
```

```sh
node tools/build-depth.mjs my-depth.mjs data-structures-extra   # writes content/depth/data-structures-extra.json
npm run check:examples                                          # runs every Python example
```

Use `String.raw` for code that contains backslashes. Examples that are shell commands (`curl`, `dig`, `openssl`) are skipped by the checker.

## Library file

`library/faculties.json` lists faculties, their departments, and each department's entry concepts. Below that level the structure comes from the concept tree.

## Checking your work

```sh
npm run check:content            # validate everything
npm run check:content -- --fix   # also rewrite files in canonical form and drop dangling links
npm run check:content -- --balance --fix   # also give repeated sibling orbs a form their siblings don't use
npm run check:content -- --all   # print every warning instead of the first forty
npm run check:examples           # run every Python code example in content/depth
```

The validator reports counts, orb distribution, unknown ids, orphans, cycles, label and summary length, and concepts with too few cross-links.
